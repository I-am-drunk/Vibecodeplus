Patterns Found:

    Payload-shape fragility (critical):
        Frequent any + optimistic property access in server CLI and route handling.
        Known crash class from previous flows (verify.data.projects.some) and equivalent risks still exist as unchecked nested access patterns.

    Migration/continuation path exists but is non-deterministic:
        Continuation creates new project and may delete source conditionally.
        No durable old→new mapping table/alias resolution.
        Source-preservation semantics are not formally guaranteed.

    Watcher/SSH lifecycle has loop risk and stale state exposure:
        Watcher stops on forbidden but lacks quarantine/circuit-breaker/remap orchestration.
        Migration does not formally reconcile watcher ownership and stale intervals.

    Chat stream terminal semantics are not exactly-once:
        Multiple terminal events can race (chat:stream:end, chat:stream:error, chat:aborted).
        Client finalizes from multiple event paths; no stream-instance identity + monotonic sequence.

    UX state consistency gaps:
        Workspace has many local states + store states with overlapping responsibility.
        Dialog flows (key recovery/continuation/credits) are not unified as one lifecycle graph.
        Heavy debug logging in render/effects risks perf noise and user confusion.

    Quality gates and test coverage are missing:
        No formal test matrix currently in repo (unit/integration/e2e/chaos/fuzz/soak absent).
        Release gating/rollback runbooks not codified.
